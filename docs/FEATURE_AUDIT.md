# ITSSS ERP feature acceptance audit

Source: the user's `ITSSS_Internal_ERP_Complete_Feature_List.txt`. The attachment explicitly excludes quotations and invoices. Currency is INR.

Reviewed on 7 October 2026. This app provides 72 module schemas and 250 seeded demo records, dynamic record forms, a responsive dashboard, reports and linked business calculations. This audit distinguishes implemented behavior from verified behavior and remaining integrations. It does **not** certify all 85 sections as fully complete.

**Core verified** means executed automated tests cover the stated core rules, rather than every item in the section. **Implemented (inspection)** means reviewed schema, engine, API or UI code provides that behavior, without an exhaustive browser test. **Partial** identifies a concrete scope or verification gap. **Integration required** identifies provider, background-worker or deployment work still needed.

### Inline dropdown revision

Searchable business choices support nested related-record creation without unmounting unfinished parent forms. Shared City, Brand, Department and Location dictionaries join existing categories, lead sources and payment methods; other eligible choices persist per field, including custom radio/multiselect fields. Role creation opens the complete role definition form. Template creation starts with the current module and Published status.

Creation requires server-authorized parent and child access, respects hidden fields, and validates labels, relation IDs and revisions. Ordinary business choices may extend without granting broad settings access. Filters, chart ranges, theme controls and implementation/security/financial posting enums remain fixed.

Desktop browser/API evidence for this revision:

## Integration and production boundaries

1. **Identity and security policies:** hosted ChatGPT sign-in establishes identity; app users must also be active workspace members. The first authenticated visitor initializes the empty workspace as owner. User `twoFactor`, `lastLogin`, company `passwordMinLength` and `sessionMinutes` are stored metadata, with no app-side password/2FA/session-policy enforcement. Login/logout/download/vault-read events require additional auditing. HTTPS and identity-provider controls belong to hosting.
2. **Messages and background execution:** WhatsApp/mail links launch external compose apps. No email/WhatsApp/push provider, delivery receipt, inbound-message synchronization or unattended scheduled worker is configured. Due/renewal automations run when authenticated workspace requests occur.
3. **Backups:** manual JSON backs up business records and attachment references; vault records stay encrypted. Restore needs the same configured vault key and existing R2 objects. There is no copied file archive, automatic daily/scheduled/offsite backup or retained restore-point blob service.
4. **Specialized workflows:** advanced approval thresholds, complete configurable policy stages, automatic document versioning, every dedicated filter, complete form-response management and bespoke document-template layouts need further implementation or acceptance testing.
5. **Device/document QA:** actual camera decoding requires BarcodeDetector support, permission and suitable hardware; manual lookup is available. PDF download, XLSX export parsing, helper/API XLSX import, QR rendering, manual lookup and API file-byte roundtrip passed. The browser import picker was blocked by extension settings. Camera scan, real-device GPS/photo/signature flows, browser import/mapping flow and every requested PDF layout still need acceptance testing.
6. **Accounting meaning:** project value/profit and cash received/expenses are presented separately. Product/service performance comes from recorded projects/material/asset history. This is an operational ERP; statutory accounting/GST filing and reconciliation to external books are not certified.
7. **Scale and operations:** one D1 workspace JSON snapshot is revision-protected. Large-scale query/indexing, load tests, recovery drills and production operational monitoring require separate acceptance work.
